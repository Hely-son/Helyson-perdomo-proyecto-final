## Contrato de interfaz para `frontend-engineer`

**1. `src/api/orders.ts`.** Todas con `apiRequest({ auth: true })`; ids con `encodeURIComponent(String(id))`. Las pruebas solo llaman directamente a `changeOrderStatus(id: number, status): Promise<OrderDetail>` → `PATCH /orders/{id}/status`, cuerpo `{ status }`. El listado y el detalle se observan por las peticiones del loader: `GET /orders` (`status`, `page`; `pageSize` omitido o 20) y `GET /orders/{id}`.

**2. `src/orders/orders.ts`** (lógica pura):

```ts
availableOrderActions(status: OrderStatus): readonly OrderTargetStatus[]
interface OrdersQuery { status: OrderStatus | null; page: number; orderId: number | null }
parseOrdersQuery(params: URLSearchParams): OrdersQuery   // parámetros de URL: status, page, order; inválido → valor por defecto
ordersSearch(query: OrdersQuery): string                 // inversa de parseOrdersQuery
withStatusFilter(query, status: OrderStatus | null): OrdersQuery   // page = 1
classifyOrderError(error: unknown): OrderErrorOutcome
runOrderAction<T>(action: () => Promise<T>, reload: () => unknown): Promise<OrderActionResult<T>>   // nunca rechaza
type OrderErrorOutcome =
  | { kind: 'session' }                                    // UNAUTHORIZED, SessionExpiredError, NoSessionError
  | { kind: 'validation'; message: string }                // VALIDATION_ERROR: mensaje de la API
  | { kind: 'conflict'; message: string; reload: true }    // INVALID_ORDER_TRANSITION: "el estado … cambió"
  | { kind: 'not-found'; message: string; reload: true }   // ORDER_NOT_FOUND: menciona el pedido
  | { kind: 'technical'; message: string; reload: true };  // red, INTERNAL_ERROR y resto: genérico, sin detalles
```

`reload` se llama una vez ante éxito, `conflict`, `not-found` y `technical`, y ninguna ante `session`. Ante `validation` no se fija.

**3. Loader de `/dashboard/orders`** (hija directa de la ruta con `protectedLoader`). Nunca lanza; no hace peticiones sin sesión vigente. Lee listado y detalle según la URL. Devuelve `status: 'ready'` cuando el listado se leyó, con `detail: null | OrderDetailState`; un fallo del detalle no oculta el listado.

```ts
type OrderDetailState =
  | { status: 'ready'; order: OrderDetail }
  | { status: 'not-found' }                       // ORDER_NOT_FOUND
  | { status: 'invalid'; message: string }        // VALIDATION_ERROR
  | { status: 'error' };                          // red, INTERNAL_ERROR
```

**4. `src/orders/OrderDetailPanel.tsx`**: exporta `OrderDetailPanel({ detail, submitting, onChangeStatus })`, el contenido del Drawer. Muestra `orderNumber`, cliente (razón social, RUT, teléfono), ítems (nombre, cantidad en su propia celda, precio, subtotal) y total tal como llegan.
